# Frontend architecture

## Stack

- TanStack Start and TanStack Router for the application shell and file-based routes.
- React 19 with TypeScript strict mode.
- React Query is provided at the root, although current workspace reads/writes do not use queries.
- Tailwind CSS v4 for styling, shadcn/Radix for reusable primitives, Lucide for UI icons, and Motion for animation.
- dnd-kit powers whole-row hierarchy dragging, while Sonner presents reversible move feedback.
- Tiptap 3 with lowlight syntax highlighting for rich-text documents.
- React Flow provides the interactive graph canvas; Dagre provides deterministic top-to-bottom
  hierarchy layout. The graph runtime loads only after hydration and after the map opens.
- Excalidraw 0.18 provides whiteboard pages and loads only after hydration and after a whiteboard
  opens.

Path alias `@/*` resolves to `src/*`.

## Runtime composition

```text
src/server.ts
  -> TanStack server entry
  -> src/routes/__root.tsx
       QueryClientProvider
       AuthProvider
       Outlet
         src/routes/index.tsx
           KnowledgeProvider
           AmbientBackground
           Sidebar
           Canvas
           Toaster
```

There is currently one product route, `/`. New routes belong in `src/routes`; never create a Next.js-style `pages` or `app` directory. `src/routeTree.gen.ts` is generated by TanStack tooling and must not be edited manually.

## Workspace state

`src/store/knowledge.tsx` is the client-side application core.

- `KnowledgeProvider` owns a `useReducer`.
- `useKnowledge()` exposes state, hydration/sync flags, the active page, and mutation functions.
- Reducer actions cover hydrate, select, typed page creation, template-add, delete, ordered page
  moves across the full hierarchy, page patch, document-content update, and whiteboard-scene update.
- `src/lib/pages.ts` holds pure page creation, deletion, ancestry, counting, and seed helpers.
- Every mutation creates a new state object, which triggers local persistence and, for authenticated users, debounced remote synchronization.

Do not mutate a page object or ordering array in a component. Add a reducer action or pure helper, then expose the smallest domain method through `useKnowledge()`.

## Data shape consumed by the UI

The persisted state is a flat page map:

```ts
interface KnowledgeOSState {
  pages: Record<string, KnowledgePage>;
  rootOrder: string[];
  activePageId: string | null;
}
```

Each page stores `parentId`, an ordered `childrenIds` list, and an optional `kind`. Missing `kind`
means a legacy document; newly created pages explicitly use `document` or `whiteboard`. Whiteboard
pages store a versioned Excalidraw element array plus compact view metadata. Binary files are
deliberately excluded from persistence.

These relationships must remain consistent:

- every root page appears once in `rootOrder` and has `parentId: null`;
- every child appears once in its parent's `childrenIds` and points back with `parentId`;
- deleted descendants are removed from the map and all ordering lists;
- `activePageId` is either `null` or a valid page ID.

The authoritative full contract is in `src/lib/types.ts`; backend persistence is described in [BACKEND.md](BACKEND.md).

## Editor architecture

`src/components/editor/block-editor.tsx` constructs one Tiptap instance per active `pageId`.

- StarterKit provides standard blocks, with its code block disabled.
- CodeBlockLowlight supplies highlighted code blocks.
- TaskList and nested TaskItem supply checklists.
- Placeholder supplies empty-editor guidance.
- `SlashCommand` in `slash-command.tsx` renders the `/` suggestion menu.
- BubbleMenu supplies bold, italic, strike, and inline-code actions.
- Editor updates are debounced for 400 ms before dispatching JSON into the workspace store.

The editor owns live ProseMirror state while the user types. The component is memoized by `pageId` specifically to prevent ordinary store updates from replacing the editor DOM and moving the cursor. Preserve this invariant when adding collaboration or remote-update behavior.

Current limitation: content changes received for the same active `pageId` do not automatically replace the live editor document because the memo comparison only checks `pageId`. Any realtime-conflict fix must preserve cursor stability while explicitly reconciling remote content.

## Images and covers

- Uploaded cover and avatar files are read through `readFileAsDataURL` in `src/lib/storage.ts`.
- The resulting data URL is stored directly on `KnowledgePage`.
- Curated covers in `cover-picker-modal.tsx` store remote Unsplash URLs instead.
- Large uploaded images therefore enlarge both IndexedDB records and the Supabase JSON document.

Do not introduce a URL-entry field as the normal upload flow. A future object-storage migration must include backward compatibility for existing data URLs and remote URLs.

## Styling and motion

`src/styles.css` contains:

- Tailwind v4 source/theme setup;
- shadcn semantic color variables;
- editor typography and block styling;
- task checkbox and syntax-highlighting rules;
- custom scrollbars;
- ambient background keyframes;
- shared glow utilities.

Component-specific layout and states belong in Tailwind classes. Add global CSS only for shared tokens, third-party editor DOM, or behavior that cannot be expressed cleanly in component utilities.

Use the existing obsidian/violet visual language. Motion should clarify state changes and hierarchy, and must respect the existing `prefers-reduced-motion` handling for ambient effects.

Looseleaf Terminal is the canonical Knowledge OS identity. Its light transparent mark appears in the
dark sidebar header, while `src/routes/__root.tsx` publishes the matching SVG, PNG, ICO, and Apple
touch icon variants from `public/brand`.

The desktop sidebar is a 264 px workspace navigator rather than a utility panel. Its expanded state
keeps capture and navigation visible, places optional tools in context, and ends with the persistent
soundscape transport and account/shortcut menu. Collapsing it produces a 56 px focus rail with only
recognizable icon actions and accessible labels; it does not squeeze expanded controls into a narrow
column. Below the desktop breakpoint, the same expanded navigation becomes a 288 px drawer (capped at
86 viewport-width units) over a dismissible scrim so the writing canvas keeps the full screen.

Cloud synchronization has no floating canvas badge. When a user is signed in, the sidebar header
shows a quiet cloud/check status with a tooltip and uses motion only while a sync is actively running.
Unsigned and local-only workspaces do not show a misleading cloud status.

The graph keeps React Flow's third-party control, edge, and minimap overrides under the
`.calm-graph` scope. `sidebar.tsx` does not statically import the graph module: it waits for
hydration, waits for the Map action, and then resolves `graph-modal.tsx` through `React.lazy` and
`Suspense`. This module boundary prevents React Flow and its browser-oriented transitive chunks from
entering the initial server module graph. Page order feeds Dagre in stable hierarchy order so
reopening or switching modes does not arbitrarily shuffle nodes. Overview renders the full tree;
Focus renders the active or selected page's ancestors, nearby siblings, children, and grandchildren.
Workspaces larger than 24 pages open in Focus mode to keep the first frame legible, while smaller
workspaces open in Overview.

## Whiteboard architecture

`whiteboard-page.tsx` uses TanStack Router's `ClientOnly` before mounting a small browser setup
component. That component configures the asset path and only then resolves `whiteboard-editor.tsx`
through `React.lazy` and `Suspense`. Excalidraw does not support server rendering, so this module
boundary keeps its code out of the initial server graph and keeps the normal document path free of
the whiteboard runtime. A render-time `window` guard around a static import is not sufficient:
bundlers may still evaluate browser-only transitive chunks while loading the SSR route. Excalidraw's
fonts are served from `public/excalidraw-assets/fonts`, and Knowledge OS-specific overrides are
scoped under `.knowledge-whiteboard`. The surrounding shell stays dark while the board uses a quiet,
high-contrast paper surface and violet default strokes.

`whiteboard-editor.tsx` keeps Excalidraw's live scene inside the editor and debounces compact scene
updates before dispatching `setWhiteboard`; pending scenes are flushed on unmount. Images, embeds,
iframes, and binary files are rejected so the whole-workspace JSON remains bounded. The board
supports Excalidraw import plus Excalidraw, PNG, and SVG export.

## Keyboard and interaction contracts

- `Ctrl/Cmd + K` toggles search.
- The New Page primary action creates a document immediately; its adjacent menu exposes whiteboards
  and templates without slowing the default capture path.
- Selecting Home, a search result, a map node, or a page closes the mobile navigation drawer.
- The closed mobile drawer is inert. Opening it moves focus to its close control and makes the canvas
  inert; Escape dismisses the topmost nested menu before it dismisses the drawer and returns focus to
  the opener. Navigation and creation do not steal focus back from the destination, while closing a
  drawer-launched tool returns focus to the visible opener.
- `/` opens the block menu.
- Arrow keys and Enter navigate/choose slash items; Escape closes the menu.
- A newly created empty page auto-focuses its title.
- Enter is blocked in the single-line auto-growing title.
- Page deletion requires a second click within three seconds.
- In the page tree, drag a page row itself to reorder it; use the row center to nest it, row edges to
  place it beside a sibling, or the temporary top-level zone to remove its parent. Short clicks still
  open pages, while expand/add/delete controls never begin a drag. Pointer drags use a small movement
  threshold and touch drags use a short hold to preserve normal scrolling.
- Graph nodes select on click, open on double-click, and clear their inspector when the canvas or inspector close control is clicked.
- Graph navigation supports drag-to-pan, wheel/pinch zoom, explicit zoom controls, and fit-to-view.
- Opening the workspace map focuses its heading instead of presenting the close control as the
  primary action. The close control stays keyboard-reachable with a restrained focus-visible state.
- Whiteboards draw directly on a touch-safe canvas; pen, eraser, color, clear, and the inline board
  title remain reachable from the Knowledge OS header and toolbar.
- Soundscape playback begins only from an explicit user action. Collapsing the desktop sidebar keeps
  an active mix playing and leaves a pause/resume control in the focus rail; reopening the sidebar
  restores the inline mixer rather than a detached popup.

Preserve keyboard behavior and add accessible labels/tooltips when introducing icon-only controls.

## Known frontend constraints

- There is no automated behavior test suite; `npm.cmd run smoke:ssr` provides a targeted
  post-build check of the generated server handler.
- Search inspects titles only, not Tiptap document text.
- The graph is optimized for hierarchical exploration, not backlinks or semantic relationships.
- `ready` exists in the store but the current UI has no dedicated hydration/loading surface.
- Responsive and mobile behavior have not been captured in automated checks.
- Excalidraw libraries are not persisted; whiteboard images, embeds, and live collaboration are
  intentionally unsupported.

When a change resolves one of these constraints, update this section and append one line to `LOG.md`.
